Serve pages in the language of the visitor. Topcoat picks a locale for each request, such as `en` or `de-CH`, and makes it available to everything that renders the page. Enable the `l10n` feature of `topcoat` to use it.

The text itself can come from anywhere. With the `l10n-fluent` feature, Topcoat translates messages from [Fluent](https://projectfluent.org/) files, as described [below](#fluent).

# Locales

A [`Locale`] identifies a language, optionally with a script, a region and other details, such as `en`, `zh-Hant` or `de-CH`. Write one with [`locale!`](macro@locale), which checks it at compile time, or parse one at runtime:

```rust
use topcoat::l10n::{Locale, locale};

const GERMAN: Locale = locale!("de");
let swiss: Locale = "de-CH".parse().unwrap();
assert_eq!(swiss.id().language(), GERMAN.id().language());
```

# Choosing the locale

Each request has a locale, which [`locale`](fn@locale) returns. Set it for every page in a [`#[layer]`](crate::router::layer), which runs before the page, by putting it in the context with [`Cx::with`](crate::context::Cx::with).

To pick the locale, [`negotiate`] compares the languages of the browser, from [`accept_language`], with the locales the app supports:

```rust,no_run
use topcoat::{
    Result,
    context::Cx,
    l10n::{Locale, accept_language, locale, negotiate},
    router::{Body, Next, layer, module_router, page, response::Response},
    view::{View, view},
};

const LOCALES: [Locale; 2] = [locale!("en"), locale!("de")];

#[tokio::main]
async fn main() {
    topcoat::start(module_router!().build()).await.unwrap();
}

#[layer]
async fn layer(cx: &Cx, body: Body, next: Next<'_>) -> Result<Response> {
    let locale = negotiate(accept_language(cx), &LOCALES)
        .cloned()
        .unwrap_or(locale!("en"));
    next.run(&cx.with(locale), body).await
}

#[page]
async fn home(cx: &Cx) -> Result<impl View> {
    Ok(view! {
        <!DOCTYPE html>
        <html lang=(locale(cx).id()) dir=(locale(cx).id().direction())>
            <body>
                <p>"The page is in " (locale(cx))</p>
            </body>
        </html>
    })
}
```

Set `lang` and `dir` on `<html>` to match the locale, as above.

A layout cannot set the locale, because the page does not render inside the scope of the layout.

To put the locale in the URL instead, as in `/en` or `/de`, declare a [`module_param!`](crate::router::module_param) of type [`Locale`] and read it in the layer. Reject the locales the app does not support, since any locale can be typed into the URL. The `examples/l10n` directory of the repository does this.

# Fluent

With the `l10n-fluent` feature, the messages of each locale live in a Fluent file named after the locale, such as `src/l10n/en.ftl`:

```fluent
title = Welcome
greeting = Hello, { $name }!
search = Search
    .placeholder = Type to search
```

and `src/l10n/de.ftl`:

```fluent
title = Willkommen
greeting = Hallo, { $name }!
search = Suche
    .placeholder = Suchbegriff eingeben
```

[`messages!`](fluent::messages) loads the files and creates `t!` to translate them. For these files, invoke `messages!("./l10n/{locale}.ftl")` in `src/main.rs`, since a path starting with `./` is relative to the source file. [`messages!`](fluent::messages) describes the other kinds of paths, and how to split a locale into several files. It also creates a `t` module, whose `t::locales()` returns the locales that have files. Pass them to [`negotiate`] in place of a list of your own.

## Translating

`t!` takes the ID of a message, followed by its arguments. Use `.name` for an attribute of the message:

```rust
# topcoat::l10n::fluent::messages!("l10n/{locale}.ftl");
let name = "Ada";
let title = t!(title);
let greeting = t!(greeting, name = "Ada");
// Short for `name = name`.
let greeting = t!(greeting, name);
let placeholder = t!(search.placeholder);
```

In a view, a translation renders as the text of the message in the locale of the request. Elsewhere, turn it into text with [`resolve`](Translation::resolve), or with [`resolve_in`](Translation::resolve_in) for another locale:

```rust
# use topcoat::{context::Cx, l10n::locale};
# topcoat::l10n::fluent::messages!("l10n/{locale}.ftl");
let cx = &Cx::default().with(locale!("de"));
assert_eq!(t!(title).resolve(cx), "Willkommen");
assert_eq!(t!(title).resolve_in(&locale!("en")), "Welcome");
```

## Regional locales

A regional locale only needs the messages that differ from its language. With `de.ftl` and `de-CH.ftl`, a message that `de-CH` lacks is taken from `de`. A locale never takes messages from another language.

## Missing messages

There is no fallback language. A message that the locale lacks renders as a placeholder made of its key and arguments, such as `greeting(name = "Ada")`, so the page can be built before every translation exists.

## Checking messages

The Topcoat CLI can report problems with an app's messages:

```sh
topcoat l10n check
```

It shows how many of the keys that `t!` uses each locale has, and reports these errors:

- a message or attribute that `t!` uses, but a locale lacks,
- a variable of a message that `t!` does not pass,
- a reference to a message, term or attribute that does not exist.

It also warns about messages that no `t!` uses, and arguments that no locale uses. A `t!` call that the compiler removed, because no code uses it, does not count. The command exits with an error when it finds errors, so it can run in CI.

`topcoat dev` runs the same check after each build, and prints a warning when there are problems.

Cargo does not notice a new `.ftl` file, so a plain `cargo build` does not include it until another file of the crate changes. `topcoat dev` rebuilds the crate when a file is added.
