# Mail

This example demonstrates how to create and send email messages with Topcoat.

It shows how to:

- configure a mail transport;
- build an HTML email;
- derive a plain-text alternative;
- add an inline image;
- add a file attachment;
- add custom email headers;
- submit recipient data through an HTML form.

The example uses a file transport. Messages are written to local `.eml` files and are not delivered to real email addresses.

## Run the example

From the repository root, run:

```sh
cargo run --manifest-path examples/mail/Cargo.toml
```

From inside the `examples` directory, run:

```sh
cargo run --manifest-path mail/Cargo.toml
```

The application is served by default at:

```text
http://127.0.0.1:3000
```

## Test in the browser

Open the application in your browser.

Enter a name and a syntactically valid email address, for example:

```text
Name: Francesco
Address: francesco@example.com
```

Click **send**.

The browser should redirect to:

```text
http://127.0.0.1:3000/sent
```

The outbox page should list a newly generated `.eml` file.

The file is stored in:

```text
examples/mail/outbox
```

## Test with curl

Remove any messages generated by earlier tests:

```sh
rm -rf examples/mail/outbox
```

From inside the `examples` directory, use:

```sh
rm -rf mail/outbox
```

Submit the form:

```sh
curl --include \
    --request POST \
    --header "Content-Type: application/x-www-form-urlencoded" \
    --data "name=Francesco&address=francesco%40example.com" \
    http://127.0.0.1:3000/send
```

The response should return a redirect to:

```text
/sent
```

Request the outbox page:

```sh
curl --silent http://127.0.0.1:3000/sent
```

The response should contain the name of a generated `.eml` file.

List the generated files from the repository root:

```sh
ls -l examples/mail/outbox
```

## Inspect the generated message

Display the beginning of the generated message:

```sh
head -n 40 examples/mail/outbox/*.eml
```

The message should contain headers similar to:

```text
From: Topcoat <welcome@example.com>
To: Francesco <francesco@example.com>
Reply-To: support@example.com
Subject: Welcome, Francesco!
List-Unsubscribe: <mailto:unsubscribe@example.com>
```

It should also contain multipart sections for:

- an HTML body;
- a plain-text alternative;
- the inline Ferris image;
- `getting-started.txt`.

You can open the `.eml` file with an email client to inspect the rendered message.

## How it works

- `MailConfig` configures the application's mail transport.
- `FileTransport` writes messages to the local filesystem.
- `.mail(config)` registers the mail configuration with the router.
- `Form<Recipient>` reads the submitted name and email address.
- `mail!` builds the email message.
- `Attachment::inline(...)` embeds Ferris and assigns it a content ID.
- `cid:ferris` displays the inline image in the HTML body.
- `Attachment::new(...)` adds the text file as a regular attachment.
- `send(cx, mail)` sends the message through the configured transport.
- `see_other("/sent")` redirects to the outbox after the message is written.

A production application would normally replace `FileTransport` with an SMTP or another delivery transport.

Stop the server by pressing `Ctrl+C`.
